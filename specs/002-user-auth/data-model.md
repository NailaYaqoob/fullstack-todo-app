# Data Model: User Authentication

**Feature**: `002-user-auth` | **Date**: 2026-02-25

---

## Entities

### User *(managed by Better Auth — do not define as SQLModel table)*

Better Auth creates and owns the `user` table via its database adapter. SQLModel does
not define `User` with `table=True`. The backend uses `UserRead` (a plain Pydantic
BaseModel) for type hints only.

| Field | Type | Constraints | Notes |
|-------|------|-------------|-------|
| id | string | PRIMARY KEY | ULID / cuid2 generated by Better Auth |
| name | string | NOT NULL | Display name; ≥1 non-whitespace char (FR-004, edge case) |
| email | string | UNIQUE, NOT NULL, INDEX | RFC 5321 format; lowercase (FR-002, FR-005) |
| emailVerified | boolean | NOT NULL, default: false | Out of scope Phase II; stored but unused |
| image | string? | NULLABLE | Avatar URL (optional, Better Auth field) |
| createdAt | timestamp | NOT NULL | UTC; account creation time |
| updatedAt | timestamp | NOT NULL | UTC; updated on any field change |

**Validation rules enforced by Better Auth**:
- `name`: trimmed; must contain at least one non-whitespace character
- `email`: validated format before insert; unique constraint at DB level
- `password`: minimum 8 characters (`minPasswordLength: 8`); stored as bcrypt hash (FR-013)

### Session *(managed by Better Auth — do not define as SQLModel table)*

Better Auth creates and owns the `session` table.

| Field | Type | Constraints | Notes |
|-------|------|-------------|-------|
| id | string | PRIMARY KEY | |
| userId | string | FK → user.id, NOT NULL | |
| token | string | UNIQUE, NOT NULL | Opaque session identifier (also used as JWT `jti`) |
| expiresAt | timestamp | NOT NULL | `createdAt + 604800s` (7 days) |
| createdAt | timestamp | NOT NULL | |
| updatedAt | timestamp | NOT NULL | |
| ipAddress | string? | NULLABLE | |
| userAgent | string? | NULLABLE | |

**State machine**:
```
active ──[user clicks sign-out]──────────► revoked  (FR-009, FR-010)
active ──[expiresAt reached / 7 days]────► expired  (FR-008)
active ──[updateAge elapsed / 1 day]─────► refreshed (new token; old revoked)
```

Multiple simultaneous sessions per user are allowed (multi-device, edge case in spec).

---

### JWT Payload *(runtime — not persisted)*

Issued by Better Auth JWT plugin on sign-in. Verified by FastAPI `verify_jwt()`.

| Claim | Type | Notes |
|-------|------|-------|
| sub | string | User ID — primary key used for `user_id` in task queries |
| email | string | User's email address |
| name | string | User's display name |
| iat | number | Issued-at (Unix seconds) |
| exp | number | Expiry = `iat + 604800` (7 days) |

`get_current_user()` returns the `sub` claim as `current_user_id: str`.

---

### Task *(from 001-task-crud feature — shown for FK reference only)*

The `Task` model lives in `backend/models.py` and belongs to feature `001-task-crud`.
Shown here to document how `user_id` links to Better Auth's `user` table.

| Field | Type | Notes |
|-------|------|-------|
| user_id | str | String field (no FK constraint); value = JWT `sub` claim |

No SQLAlchemy FK constraint is defined — the relationship is enforced at the application
layer by Principle III (JWT-verified `user_id` filtering on every query).

## Entity Relationships

```
Better Auth manages:
  User (1) ────────────── (N) Session
  User (1) ────────────── (N) Account     [OAuth, not used Phase II]
  User (1) ────────────── (N) Verification [email verify, not used Phase II]

SQLModel manages (future, 001-task-crud):
  User (1) ────────────── (N) Task
    user.id  ←→  task.user_id (string reference, no FK constraint)
```

## Backend SQLModel Definitions

```python
# backend/models.py

from pydantic import BaseModel
from datetime import datetime

# Read-only reference type for route handler responses.
# NOT a database table — Better Auth owns the user table.
class UserRead(BaseModel):
    id: str
    name: str
    email: str
    created_at: datetime
```

The actual `user` and `session` tables are created by Better Auth's startup migration.
SQLModel's `create_db_and_tables()` must NOT attempt to create these tables.

---

## Better Auth Tables Created at Startup

Better Auth calls its own schema migration on startup via the database adapter.
Tables created automatically (do not replicate in SQLModel):

| Table | Owner | Purpose |
|-------|-------|---------|
| `user` | Better Auth | Account records |
| `session` | Better Auth | Active sessions (JWT-linked) |
| `account` | Better Auth | OAuth provider accounts (unused Phase II) |
| `verification` | Better Auth | Email/phone verification tokens (unused Phase II) |
